SPY-3697 — HOW TO USE
======================

This guide walks you through setting up and running SPY-3697 from scratch on
Kali Linux. Follow the steps in order.


STEP 1 — Set up a Python virtual environment
---------------------------------------------
From inside the spy3697 folder:

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt

You should see packages like typer, fastapi, and anthropic get installed.
If any step fails, note the error before continuing.

Remember: every time you open a new terminal to use SPY-3697, you need to
re-activate the virtual environment first:

    source .venv/bin/activate


STEP 2 — Install the external security tools it wraps
--------------------------------------------------------
SPY-3697 does not reimplement scanning logic itself — it shells out to
well-known, purpose-built security tools and captures their real output.
Install them:

    sudo apt update
    sudo apt install nmap sqlmap gobuster tshark whatweb -y

Nuclei and httpx are Go-based tools, installed separately:

    sudo apt install golang-go -y
    go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
    go install github.com/projectdiscovery/httpx/cmd/httpx@latest
    go install github.com/hahwul/dalfox/v2@latest

Trivy (supply-chain / dependency scanning) has its own install script:

    curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh -s -- -b /usr/local/bin

Make sure ~/go/bin is on your PATH (Kali's default shell is zsh):

    echo 'export PATH=$PATH:~/go/bin' >> ~/.zshrc
    source ~/.zshrc

(If you're using bash instead of zsh, edit ~/.bashrc and run
`source ~/.bashrc` instead.)

Confirm everything is found:

    which nmap sqlmap gobuster tshark nuclei httpx dalfox trivy

Every one of those commands should print a file path. If any print nothing,
that tool isn't installed correctly — revisit its install step above.


STEP 3 — Create your config file
-----------------------------------
Copy the example config to a real one:

    cp config.example.yaml config.yaml

Open it in a text editor:

    nano config.yaml

Edit two things:

1. authorized_targets — add the IP/hostname of a target you are actually
   allowed to test (a HackTheBox/TryHackMe box IP, a VulnHub VM, your own
   lab, or a signed engagement scope). Example:

       authorized_targets:
         - 10.10.10.5
         - 192.168.56.0/24    # a whole local lab subnet also works

   SPY-3697 refuses to run any active module (port scans, sqlmap, exploit
   verification, packet capture, command execution) against anything not on
   this list, unless you separately confirm authorization with the
   --i-confirm-authorization flag at run time. This is a hard safety gate —
   see LEGAL_AND_ETHICAL_USE.md. Only ever test systems you own or have
   explicit written permission to test.

2. llm section — leave provider as "anthropic" if you're using Claude
   (default), or change it to "openai_compatible" or "ollama" if you're
   using a different backend. See README.md for details.

Save and exit nano: Ctrl+O, then Enter, then Ctrl+X.


STEP 4 — Choose an LLM backend: Anthropic (paid) or Ollama (100% free, local)
---------------------------------------------------------------------------------
SPY-3697 supports three backends. Anthropic (Claude) needs an API key and
billing credits. Ollama runs a model entirely on your own machine, for
free, with no API key and no internet connection needed once installed.
Quality is lower than Claude but it costs nothing.

  OPTION A — Ollama (free, local, no API key, no billing)
  -----------------------------------------------------------
  1. Install Ollama:

      curl -fsSL https://ollama.com/install.sh | sh

  2. Pull a model. If you don't have a GPU (check with `nvidia-smi` or
     `lspci | grep -i vga`), pick a small model so it doesn't crawl on CPU:

      ollama pull llama3.2:3b

     If you do have a GPU, or want better quality and don't mind it being
     slower, a bigger model follows instructions more reliably:

      ollama pull llama3.1:8b

  3. Confirm it's running (the installer sets this up as a systemd service
     automatically):

      systemctl status ollama
      ollama run llama3.2:3b "say hello"

  4. Point config.yaml at it:

      llm:
        provider: ollama
        model: llama3.2:3b
        base_url: http://localhost:11434/v1
        max_tokens: 4000
        temperature: 0.2

     No api_key or api_key_env needed for this provider.

  CAVEAT: smaller local models sometimes don't follow the strict JSON-only
  output format SPY-3697's identify/verify stages require as reliably as
  Claude does. If you see "LLM proposal failed to parse" errors often, try
  a larger model (llama3.1:8b, qwen2.5:14b if your hardware allows).

  On CPU-only machines, LLM calls during the identify/verify stages will
  be noticeably slower than with the Anthropic API -- this is expected,
  not a bug. Give it time before assuming it's stuck.

  OPTION B — Anthropic / Claude (paid, needs API key + billing credits)
  -----------------------------------------------------------------------
  Get a key from https://console.anthropic.com/settings/keys and add
  credits at https://console.anthropic.com/settings/billing (the API
  requires a positive credit balance even with a valid key -- a key alone
  is not enough).

  Then in config.yaml:

      llm:
        provider: anthropic
        model: claude-sonnet-5
        api_key_env: ANTHROPIC_API_KEY
        api_key: "sk-ant-your-actual-key-here"

  config.yaml is already listed in .gitignore, so this key stays only on
  your machine and is never pushed to GitHub.

  Alternative to putting the key in config.yaml -- an environment variable
  (has to be re-set per terminal session unless added to your shell config):

      export ANTHROPIC_API_KEY="your-actual-api-key-here"
      echo 'export ANTHROPIC_API_KEY="your-actual-api-key-here"' >> ~/.zshrc
      source ~/.zshrc

  (If you use bash instead of zsh, edit ~/.bashrc and run
  `source ~/.bashrc` instead.)

  NOTE: if you set api_key directly in config.yaml, it always takes
  priority over this environment variable -- you only need one or the
  other, not both.

  OPTION C — OpenAI-compatible endpoint (OpenAI, Azure OpenAI, etc.)
  -----------------------------------------------------------------------
      llm:
        provider: openai_compatible
        model: gpt-4o-mini
        api_key: "sk-your-key-here"
        base_url: https://api.openai.com/v1   # or your Azure endpoint


STEP 5 — Install the spy3697 command (optional but recommended)
--------------------------------------------------------------------
    pip install -e .

This lets you run `spy3697 ...` directly instead of `python -m spy3697.cli ...`.


STEP 6 — Run it
------------------
One-click full pipeline (recon -> identify -> verify -> report + PoC) against
your authorized target:

    spy3697 run 10.10.10.5 --i-confirm-authorization --goal "Check this target for common vulnerabilities"

Replace 10.10.10.5 with your actual authorized target's IP or hostname.

Results are written to:

    workspace/<target>/<run_id>/report.md
    workspace/<target>/<run_id>/poc/*.sh

Run individual stages instead of the full pipeline:

    spy3697 recon 10.10.10.5 --i-confirm-authorization
    spy3697 scan 10.10.10.5 --run-id <run_id_from_recon>
    spy3697 verify 10.10.10.5 --run-id <run_id> --finding-id <id>
    spy3697 report --run-id <run_id> --target 10.10.10.5 --formats md,docx

Or launch the local web interface instead of the CLI:

    spy3697 web --port 8765

Then open http://127.0.0.1:8765 in your browser. Enter the target, check the
authorization confirmation box, and watch the pipeline run live. The web UI
also shows a live findings radar and a coverage matrix of which vulnerability
categories are auto-scanned vs. assist-only vs. manual.


STEP 7 — New standalone scans (XSS, supply chain, authorization checks, AI probes)
--------------------------------------------------------------------------------------
    spy3697 xss 10.10.10.5 --url http://10.10.10.5/search?q=test --run-id <id> --i-confirm-authorization

    spy3697 sca 10.10.10.5 --path ./my-project --run-id <id>
        (scans a local folder's dependencies for known-vulnerable packages;
        no network target involved)

    spy3697 authz-check 10.10.10.5 \
        --url-template "http://10.10.10.5/api/orders/{id}" \
        --ids 1,2,3,4 --run-id <id> --i-confirm-authorization
        (IDOR/BOLA assist -- fetches each id and shows you the responses
        side by side; you decide whether access should have been denied)

    spy3697 ai-probe-cmd 10.10.10.5 --url http://10.10.10.5/chat \
        --run-id <id> --i-confirm-authorization
        (sends benign prompt-injection canary strings to an AI-backed
        endpoint and shows you the responses)


A NOTE ON GETTING BLOCKED / RATE LIMITED
--------------------------------------------
SPY-3697 does not rotate IPs or identities to dodge a block. In a real
authorized engagement your IP is normally whitelisted by the client, and
being blocked by a WAF/rate-limiter is itself worth reporting, not something
to route around. If you're hitting rate limits during a legitimate test,
lower limits.rate_limit_requests_per_sec in config.yaml to slow the tool
down instead.


TROUBLESHOOTING
------------------
"spy3697: command not found"
    Run `pip install -e .` from inside the spy3697 folder (Step 5), or use
    `python -m spy3697.cli run ...` instead.

"Authorization error: '...' is not in authorized_targets..."
    Add the target to config.yaml under authorized_targets (Step 3), or add
    --i-confirm-authorization to your command.

A tool wrapper reports "tool binary not found"
    That specific external tool (nmap/nuclei/sqlmap/etc.) isn't installed or
    isn't on your PATH. Revisit Step 2 and re-run the `which ...` check.

LLM calls fail / "No API key found. Set 'api_key' directly in config.yaml..."
    Revisit Step 4 -- either add api_key: "sk-ant-..." under llm: in
    config.yaml (Anthropic/OpenAI-compatible), or make sure ANTHROPIC_API_KEY
    is actually exported in the terminal you're running from.

"Your credit balance is too low to access the Anthropic API"
    Your Anthropic API key is valid but your account has no billing
    credits. Add them at https://console.anthropic.com/settings/billing,
    or switch provider to "ollama" in config.yaml to avoid billing
    entirely (see Step 4, Option A).

"LLM proposal failed to parse" with provider: ollama
    The local model didn't return valid JSON. Try a larger model
    (ollama pull llama3.1:8b or qwen2.5:14b) and update config.yaml's
    llm.model to match -- bigger models follow the strict JSON-only
    instructions more reliably than small ones like llama3.2:3b.

Ollama responses are very slow
    Expected on CPU-only machines (check with `nvidia-smi`; if that
    command doesn't exist, you don't have an NVIDIA GPU). A smaller model
    (llama3.2:3b) is noticeably faster than larger ones on CPU. This is
    a hardware limitation, not a SPY-3697 bug.
